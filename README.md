# FiberTrack

Рентабельность автопарка: прибыль по машинам, рабочие дни, топливо, сверка и отчёт для руководителя.
Продукт Fiber Software.

**Состав:** PostgreSQL 16, сервер на Python 3.12 (FastAPI), интерфейс (HTML + ECharts), Caddy для HTTPS
и ежедневный бэкап. Всё запускается одной командой через Docker.

## Что умеет эта версия

| Кто | Что видит и делает |
|---|---|
| **Владелец** | Всё. Плюс экраны «Месяцы» (открыть, закрыть, переоткрыть) и «Настройки». |
| **Руководитель** | Дашборд, машины, карточка машины, тепловая карта, топливо, годы выпуска, динамика, сверка, отчёт A4 (печать в PDF), выгрузка в Excel. Справочник машин — только просмотр. Ничего не меняет. |
| **Бухгалтер** | Справочник машин (добавить, изменить госномер, прицеп, амортизацию, вывести из парка), ввод данных по машинам за открытые месяцы, шаблон месяца в Excel, очередь «Проверить». Прибыль, итоги, графики и отчёты ему не видны: сервер их просто не отдаёт. |

Каждое изменение справочника и статуса месяца пишется в журнал: кто, когда, что было и что стало.

**В следующих версиях:** разбор загружаемых файлов (шаблон, 1С, график, заправки, «АВТО») с предпросмотром
и откатом, серверный PDF, демо-данные для показов.

## Запуск на своём компьютере (Mac, Windows, Linux)

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запустите его.
2. Скачайте проект и откройте папку в терминале.
3. Создайте файл настроек:
   ```bash
   cp .env.example .env
   ```
   В `.env` задайте `DB_PASSWORD` — любой длинный пароль. Остальное для компьютера оставьте как есть
   (`SITE_ADDRESS=:80`, `COOKIE_SECURE=false`).
4. Запустите:
   ```bash
   docker compose up -d
   ```
   Первый запуск занимает несколько минут: скачиваются образы и собирается сервер.
5. Заведите пользователей. Пароль программа спросит; он должен быть не короче 10 символов.
   ```bash
   docker compose exec backend python -m app.cli create-user owner admin "Иван Петров"
   docker compose exec backend python -m app.cli create-user boss viewer "Руководитель"
   docker compose exec backend python -m app.cli create-user buh input "Бухгалтер"
   ```
   Роли: `admin` — владелец, `viewer` — руководитель, `input` — бухгалтер.
   Повторная команда с тем же логином меняет пароль и роль.
6. Загрузите историю из своих файлов (подробности в разделе ниже).
7. Откройте **http://localhost** и войдите.

## Импорт истории из ваших Excel

Положите файлы в папку `data/` рядом с `docker-compose.yml` и запустите импорт:

```bash
chmod 644 data/*.xlsx      # на Mac и Linux: сервер должен иметь право прочитать файлы
docker compose exec backend python -m app.cli import-history "/data/прибыль_по_машинам.xlsx" "/data/парк.xlsx"
```

Импорт занимает около 30 секунд. В конце он печатает, сколько машин, месяцев, заправок и спорных пунктов загрузил.

- **Повторный запуск** заменяет импортированные данные: график, прибыль, заправки, сводку простоев.
- **Правки, сделанные в программе, остаются:** справочник машин, ручной ввод бухгалтера, статусы месяцев.
- **Месяцы с внесённой прибылью** закрываются, следующие после них открываются.
- **Всё, что не сопоставилось** (например, машины без госномера), попадает в очередь «Проверить». Программа ничего не угадывает.

Файлы из `data/` в git не попадают.

## Деплой на VPS

Подойдёт сервер с Ubuntu 22.04 или 24.04, 2 ГБ памяти и доменом, который указывает на IP сервера.

```bash
# на сервере
curl -fsSL https://get.docker.com | sh
git clone <адрес репозитория> fibertrack && cd fibertrack
cp .env.example .env
nano .env        # DB_PASSWORD=…, SITE_ADDRESS=fibertrack.ваш-домен.ru, COOKIE_SECURE=true
docker compose up -d
```

Caddy сам получит HTTPS-сертификат для домена. Порты 80 и 443 должны быть открыты.
Дальше — пользователи и импорт истории, как выше. Файлы на сервер можно скопировать так:
`scp *.xlsx root@сервер:fibertrack/data/`.

**Обновление:** `git pull && docker compose up -d --build`. Миграции базы применяются сами при старте.

## Месяцы

Бухгалтер вносит данные только в **открытые** месяцы.

| Действие | Как |
|---|---|
| Текущий месяц | открывается сам 1-го числа |
| Открыть заранее (например, ноябрь) | Владелец → «Месяцы» → «Открыть для ввода». Не дальше трёх месяцев вперёд |
| Закрыть месяц | «Закрыть». После этого месяц не меняется |
| Переоткрыть закрытый | «Переоткрыть» с обязательной причиной, она попадает в журнал |

## Добавить машину

«Справочник машин» → «Добавить машину» (владелец или бухгалтер).

- **Короткий номер:** как в ваших таблицах — `885`, `078`. Если номер есть у двух машин, добавьте букву марки: `308 М`, `308 Д`, `020 Ф`.
- **Госномер:** в формате `Т970ОН58`. Латиницу и пробелы программа исправит сама.

Новая машина в работе сразу попадает в шаблон месяца.

## Бэкапы

Контейнер `backup` раз в сутки кладёт копию базы в папку `backups/` и хранит её 30 дней
(срок задаётся `BACKUP_KEEP_DAYS` в `.env`). Папку `backups/` стоит копировать за пределы сервера.

Восстановление из копии:
```bash
docker compose stop backend
gunzip -c backups/fibertrack_ДАТА.sql.gz | docker compose exec -T db psql -U fibertrack -d fibertrack
docker compose start backend
```
Восстанавливайте в пустую базу. Если в базе уже есть данные, сначала удалите том `db-data`
(`docker compose down`, затем `docker volume rm fibertrack_db-data`) и запустите заново.

## Безопасность

- Пароли хранятся в виде хэшей bcrypt.
- Сессия передаётся в cookie, недоступной скриптам страницы (httpOnly). На сервере cookie передаётся только по HTTPS.
- Каждое изменение требует CSRF-токен.
- После 5 неудачных попыток входа за 15 минут вход по этому логину приостанавливается на 15 минут.
- Права проверяются на сервере в каждом запросе. Тест перебирает все маршруты API и проверяет, кому они доступны.

## Для разработчика

```bash
# база для разработки: любой PostgreSQL 16
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
export FT_DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/fibertrack FT_COOKIE_SECURE=false
.venv/bin/alembic upgrade head
.venv/bin/uvicorn app.main:app --reload          # http://localhost:8000

# тесты: нужна пустая база fibertrack_test
FT_TEST_DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/fibertrack_test .venv/bin/pytest -q
# + проверка цифр на ваших файлах:
FT_TEST_PROFIT=../data/прибыль_по_машинам.xlsx FT_TEST_PARK=../data/парк.xlsx .venv/bin/pytest -q

# браузерный тест трёх ролей (нужны пользователи owner, boss, buh с одним паролем)
cd ../e2e && npm install && npx playwright install chromium
BASE=http://localhost FT_E2E_PASSWORD=… npm test
```

Структура:

| Путь | Что там |
|---|---|
| `backend/app/` | сервер: `models.py` (таблицы), `security.py` (вход и права), `data.py` (данные экранов по ролям), `routers/` (API), `parsing.py` + `importer.py` (разбор xlsx и импорт) |
| `backend/alembic/` | миграции базы |
| `frontend/` | интерфейс |
| `deploy/` | Caddy и бэкап |
| `docs/` | схема базы и экраны |
| `prototype/` | прежний прототип одним HTML-файлом (для справки) |
